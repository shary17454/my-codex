# تقرير تحديث iOS لتطبيق وش الرأي

## الملخص

تم تحديث تطبيق وش الرأي الأصلي المبني بـSwiftUI دون تغيير Bundle ID أو Team أو Signing أو Entitlements. شملت الجولة إعادة تصميم التدفقات الأساسية، تنظيم الملفات، إصلاح منطق التصويت والنتائج، إضافة اختبارات، والتحقق من البناء والأرشفة محليًا.

## التقنية والمعمارية

- Swift 6 وSwiftUI.
- iOS 17 كحد أدنى.
- MVVM باستخدام `HomeViewModel` و`CreateComparisonViewModel`.
- Observation لحالة ViewModels وObservableObject لجلسة المستخدم.
- URLSession للـAPI.
- Keychain للبيانات الحساسة.
- UserDefaults وJSON للتخزين المحلي والبيانات الأولية.
- لا توجد Dependencies خارجية.

## Design System

أضيف `DesignSystem.swift` ويحتوي على:

- ألوان Semantic من النظام.
- أسطح ومقاسات موحدة بزاوية لا تتجاوز 8 نقاط.
- أنماط أزرار واضحة وحالات Disabled وPressed.
- مكونات للعناوين والحالة والمؤشرات.
- عرض محتوى أقصى مناسب لـiPad.
- دعم Light/Dark دون فرض Color Scheme.

## الواجهات

- الرئيسية: هوية واضحة، مؤشرات، رؤى، قوالب سريعة، ومقارنات حديثة.
- الاكتشاف: بحث وتصنيفات وفرز وحالات فارغة وسحب للتحديث.
- المقارنة الذكية: اختيار متعدد ونتيجة متكيفة، مع تخطيط جانبي على iPad.
- التفاصيل: الخيارات أولًا قبل التصويت، ثم النتائج والملخص بعد التصويت.
- الإنشاء: Form منظم، تحقق عربي، معاينة، وحفظ مسودة.
- المكتبة: شبكة متكيفة ومعلومات منظمة.
- الحساب: تسجيل Apple والاسم المستعار والاهتمامات، مع إعدادات Backend في Debug فقط.

## جودة الكود

تم تقليص `ContentView.swift` من قرابة 2800 سطر إلى حاوية تنقل بحوالي 235 سطرًا، ونقلت الشاشات إلى ملفات Features مستقلة. لم يتغير السلوك أثناء الفصل، وأعيد تشغيل Build والاختبارات بعده.

## إصلاحات المنطق

- الثقة = 0 عندما لا توجد أصوات.
- لا يظهر فائز قبل وجود بيانات.
- التصويت عبر Backend ينتظر استجابة الخادم.
- منع ضغط التصويت المتكرر أثناء الإرسال.
- لا تتم زيادة العداد محليًا عند فشل الخادم.
- لا تُمسح المسودة ولا يُدّعى نجاح النشر عند فشل الخادم.
- Requests لها مهلات صريحة، وعمليات POST لا يعاد تنفيذها تلقائيًا.
- المسودات والبحث والتصفية والتحقق مغطاة باختبارات.

## العربية وAccessibility

- RTL مفعل في تدفق التطبيق.
- leading/trailing وتخطيطات متكيفة.
- Dynamic Type عبر أنماط النظام.
- نصوص النسب والأرقام إلى جانب الأشرطة، فلا يعتمد المعنى على اللون.
- Accessibility labels وtraits للعناصر المهمة.
- تم فحص الشاشات بصريًا على iPhone وiPad في الوضعين.
- يبقى Accessibility Inspector وVoiceOver على جهاز فعلي خطوة يدوية.

## الأمان والخصوصية

- لا توجد أسرار مضمنة.
- نقل معرف Apple والبريد المخزنين إلى Keychain مع ترحيل القيم السابقة.
- إعداد Backend والرمز ظاهر في Debug فقط.
- لا توجد أذونات زائدة.
- لم تتغير Capabilities أو Signing.
- مراجعة Privacy Labels مسؤولية يدوية قبل النشر.

## الاختبارات

- 8 Unit Tests: التحقق، التكرار، البحث، المسودة، الفائز، النسب، الفارق، الثقة، وسياسة النشر والتصويت.
- 1 UI Smoke Test: فتح التطبيق، التبويبات، شاشة الاكتشاف، والبحث.
- Backend Smoke Test مع ملف بيانات داخل `/tmp`.
- Static Analyzer وDebug/Release builds نجحت.

## الأداء

- استخدام LazyVStack وLazyVGrid للقوائم.
- تحديد عرض المحتوى على iPad.
- عدم تنفيذ زيادة Optimistic غير مؤكدة للتصويت.
- لا توجد ادعاءات رقمية عن الذاكرة أو الطاقة لأن Instruments لم يُشغّل.

## قيود الإصدار

الأرشيف المحلي غير موقّع ومخصص للتحقق البنيوي. يجب إنشاء Archive جديد وموقّع داخل Xcode Cloud باستخدام إصدار Xcode إنتاجي تسمح به Apple، ثم مراجعة الخصوصية وBackend قبل النشر العام.
