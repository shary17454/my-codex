# تقرير إكمال موارد وإصدار بطل الدروب

التاريخ: 3 أغسطس 2026
التطبيق: **بطل الدروب**
الإصدار المحلي: `2.4 (172)`
الحالة: `تم التحقق محليًا - يلزم فصل الموارد قبل الرفع`

## 1. نطاق العمل

اقتصر العمل على الجذر الرسمي لتطبيق بطل الدروب. لم يتم تغيير Bundle ID أو Development Team أو Signing أو Entitlements أو Capabilities، ولم تُعدّل ملفات الموردين غير المرتبطة ضمن هذا النطاق.

## 2. التسجيل وتجربة البداية

- أصبحت شاشة الترحيب هي أول شاشة عند التثبيت الجديد.
- لا يمكن دخول التطبيق دون بريد إلكتروني صحيح.
- تتوفر عمليتا **تسجيل جديد** و**تسجيل الدخول**.
- حُذف خيار الضيف من الواجهة ومن نموذج الوصول المحفوظ.
- أُعيد ضبط عرض صورة الترحيب والتدرج والنص بعرض وارتفاع صريحين، ثم تم التحقق بصريًا من عدم القص في العربية RTL.
- اختبر التشغيل المتكرر أن الحساب المحلي يبقى محفوظًا وأن شاشة الترحيب لا تُعرض مجددًا بعد اكتمال التسجيل.

## 3. الشاشة الرئيسية والأجيال

- البطاقة الرئيسية أصبحت مضغوطة بعد نقل الصورة الكبيرة إلى شاشة الترحيب.
- السنوات الظاهرة:
  - Y60: `1988-1997`
  - Y61: `1997-2025`
  - Y62: `2010-2025`
  - Y63: الأحدث
- تمت معاينة الصورة الحقيقية لـY60 داخل التطبيق.
- أزيلت العبارات الداخلية التي كانت تصف طلبات التطوير ولا يجوز أن يراها المستخدم.

## 4. البحث والذكاء المحلي

- اختبر البحث الطبيعي العربي عن `ذراع دركسون` بنجاح.
- اختبرت المرادفات واللهجات الشائعة للقطع.
- يوجد اختبار يمنع اعتبار الصامولة أفضل نتيجة عند طلب `ديكور القير العنابي`.
- المساعد الحالي يستطيع استخدام نتائج الكتالوج وبيانات السيارة محليًا مع حجب الأرقام المقفلة وعدم إرسال VIN.
- توجد طبقة عميل وخادم AI واختبارات حماية، لكن بناء Release الحالي لا يحتوي عنوان خادم أو رمز عميل؛ لذلك لا يوجد اتصال بخدمة AI مستضافة حتى نشر backend آمن وتكوين متغيرات البناء.

## 5. موارد الكتالوج

تم فحص المشروع المحلي ومصادر iCloud المحددة وموضع OneDrive المحلي. لم توجد بصمة فريدة في مصادر iCloud المحددة غير موجودة في الأرشيف الرسمي. كان موضع OneDrive المحلي فارغًا وقت الفحص.

| ملفات PDF في البيان | 640 |
| ملفات PDF الفعلية | 640 |
| البصمات الفريدة | 612 |
| الحجم الإجمالي | 12.51 GiB |
| Y60 | 297 |

تم استكمال 28 قيمة SHA-256 كانت ناقصة. تطابقت مسارات manifest مع فهرس البحث، وتحققت الأحجام والبصمات لكل الملفات في:

1. المصدر الرسمي للتطبيق.
2. نسخة `BatalAlDroob-Complete-Project/Source-Code`.
3. حزمة Release غير الموقعة الناتجة من Xcode.

## 6. النسخة الأرشيفية

- نُسخ المصدر والاختبارات والوثائق والموارد إلى حزمة المشروع الكاملة.
- استُخدم APFS clone copy لتجنب استهلاك 12.51 GiB إضافية فورًا مع الحفاظ على ملفات مستقلة في شجرة الأرشيف.
- أُجري `rsync --checksum` بين المصدر الرسمي والنسخة الأرشيفية؛ لم تظهر فروقات محتوى، وكانت الفروق المرصودة في أوقات المجلدات فقط.
- يوجد ملف بصمات نصي لجميع الموارد داخل `Documentation/CATALOG_RESOURCES_SHA256.txt`.
- ملف PDF للتوثيق يُحدّث من المصدر الحالي ويحتوي الكود الكامل لملفات Swift، مع جرد الموارد ونتائج التحقق.

- iPhoneOS SDK `26.5`
- iOS minimum `17.0`

كان البناء محليًا وغير موقع. احتوى 640 ملف PDF واجتاز التحقق الكامل للبصمات.

## 9. مانع App Store

بلغ حجم `.app` الناتج قرابة 13 GB، بينما حد Apple المنشور لحجم تطبيق iOS/iPadOS غير المضغوط 4 GB. لذلك لا يجوز رفع هذا البناء كما هو. كذلك ملفات PDF مستثناة من Git، فلا يستطيع Xcode Cloud الوصول إليها من checkout الحالي.

الحل الإنتاجي المطلوب:

1. إبقاء فهارس البحث والبيانات الأساسية الصغيرة داخل التطبيق.
2. نقل PDFs إلى Apple-hosted Background Assets أو تخزين خاص آمن.
3. تنزيل الكتالوج المطلوب فقط، مع استئناف التنزيل والتخزين المؤقت والتحقق من SHA-256.
4. تطبيق صلاحيات الوصول المدفوع قبل إصدار رابط التنزيل.
5. اختبار العمل دون شبكة، حذف الكاش، وحدود مساحة الجهاز.
6. إنشاء بناء جديد أصغر من حد Apple ثم تشغيل الاختبارات وStoreKit Sandbox وTestFlight.

## 10. ما لم يتم الادعاء به

- لم يُرفع هذا البناء إلى GitHub أو Xcode Cloud أو App Store Connect.
- لم يُرسل للمراجعة.
- لم يُنشر backend للذكاء الاصطناعي.
- لم تُعتبر مخالفات SwiftLint منجزة أو مخفية.

هذه البنود موثقة بهذه الصيغة حتى لا تختلط نتائج التحقق المحلي مع حالة خدمات خارجية لم تُنفذ فعليًا.
