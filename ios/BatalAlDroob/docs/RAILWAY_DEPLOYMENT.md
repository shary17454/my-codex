# نشر خادم بطل الدروب على Railway

الخدمة الوحيدة القابلة للنشر في هذا التطبيق هي **`ai-backend`** — خادم Node بلا تبعيات
يُوسّط بين التطبيق وOpenAI حتى لا يحمل التطبيق مفتاح المزوّد.

## الحالة

| البند | القيمة |
|---|---|
| Project | **بطل الدروب** (موجود مسبقاً — لم يُنشأ جديد) |
| Project ID | `77f55b7b-54c2-4390-be07-20ed4845123f` |
| Service | `batal-ai-backend` |
| Environment | `production` |
| المصدر | GitHub `shary17454/my-codex` فرع `main` |
| النطاق | `batal-ai-backend-production.up.railway.app` |
| قاعدة بيانات | **لا** — الخدمة بلا حالة |
| Redis | **لا** — انظر «لماذا لا كاش» أدناه |

## ما تم التحقق منه على النشر الحيّ

```
GET  /health                      → 200 {"ok":true,"aiConfigured":false}
POST /api/ai/chat  بلا رمز        → 401 unauthorized
POST /api/ai/chat  برمز صحيح      → 503 missing_openai_api_key
POST /api/ai/chat  رسالة فارغة    → 400 invalid_message_length
GET  /nope                        → 404 not_found
```

الـ503 هو **النتيجة المتوقعة والصحيحة**: المصادقة مرّت والتحقق مرّ ووصل الطلب إلى طبقة
المزوّد، ولا ينقص إلا المفتاح.

## متغيرات البيئة

| المتغير | الحالة | ملاحظة |

| `BATAL_AI_CLIENT_TOKEN` | ✅ مضبوط | 48 محرفاً عشوائياً، وُلِّد عند النشر |
| `AI_MODEL` | ✅ `gpt-4.1-mini` | |

لإضافة المفتاح:

```sh
cd ios/BatalAlDroob/ai-backend
railway variables --set "OPENAI_API_KEY=sk-..."
```

لقراءة رمز العميل عند الحاجة لوضعه في إعدادات بناء Xcode:

```sh
railway variables --kv | grep BATAL_AI_CLIENT_TOKEN
```

## ربط التطبيق بالخادم

التطبيق يقرأ قيمتين من `Info.plist` تُحقنان من إعدادات البناء. بدونهما يعمل المساعد
المحلي فقط — وهذا سلوك مقصود وليس عطلاً:

```
AIAssistantBaseURL     = https://batal-ai-backend-production.up.railway.app
AIAssistantClientToken = <قيمة BATAL_AI_CLIENT_TOKEN>
```

`BatalRemoteAIService` يرفض أي إعداد غير مكتمل: يشترط `https`، ورمزاً بطول 16 محرفاً على
الأقل، ويرفض قيم `$(...)` غير المستبدلة. وعند فشل الاتصال يسقط تلقائياً إلى المساعد
المحلي بدل أن يُظهر خطأ.

## لماذا Dockerfile ولا Nixpacks

`my-codex` مستودع متعدّد التطبيقات: جذره يحوي بيان Flutter وتطبيق ويب قديم وعدة مشاريع
iOS. أول بناء من الجذر اكتشف **Python** وشغّل تطبيق الويب القديم على منفذ ثابت `5005` —
خدمة لا يستطيع بروكسي Railway الوصول إليها ولا علاقة لها بالخادم.

الحل الصحيح هو Root Directory، لكنه إعداد لوحة تحكم فقط: لا يملك CLI راية له، ورفضت
الواجهة رمز جلسة CLI. فاستُخدم `RAILWAY_DOCKERFILE_PATH` — وهو أفضل هنا على أي حال: يبقى
تعريف النشر داخل التطبيق صاحبه، وتنسخ الصورة ملفين فقط بدل مئات الميغابايت من بيانات
الكتالوج ومشاريع Xcode المجاورة.

## لماذا لا قاعدة بيانات ولا كاش

الخادم بلا حالة: يستقبل طلباً، ينقّح سياقه، يسأل OpenAI، يرد. لا يحفظ شيئاً بين الطلبات
(`store: false` في نداء المزوّد أيضاً). محدِّد المعدّل الوحيد فيه `Map` داخل العملية،
ولهذا ثُبِّتت النسخ على **واحدة** في `railway.json` — لو تعدّدت النسخ لاحتفظت كل واحدة
بعدّادها وتضاعف الحد الفعلي. عند الحاجة لتوسيع أفقي حقيقي، حينها فقط يصبح Redis مبرَّراً.

## الأمان

- لا أسرار في الكود ولا في Git؛ كلها متغيرات بيئة.
- الحاوية تعمل بمستخدم `node` لا `root`.
- الخادم يربط `0.0.0.0` فقط حين تحقن المنصة `PORT`؛ التشغيل المحلي يبقى على loopback.
- `redactSensitiveText` يحجب أرقام الهياكل والمفاتيح وكلمات المرور قبل الإرسال للمزوّد،
  و`maskPotentialPartNumbers` يحجب أرقام القطع غير المفتوحة.
- الحدّ 20 طلباً/دقيقة لكل (IP + رمز)، وحجم الجسم الأقصى 32KB.

## ⚠️ النشر التلقائي لا يعمل حالياً

**الدفع إلى `main` لا يبني تلقائياً.** رُصد هذا مرتين: كوميت `fa62284` لم يُبنَ حتى
أُعيد ربط المصدر يدوياً، وكوميت `8bfa404` لم يُبنَ أصلاً.

**السبب الجذري:** رَبْط المصدر تطلّب راية `--branch`، وتوثيق CLI يقول صراحة إنها
للمستودعات *غير المرئية عبر تطبيق Railway على GitHub*. وبدون وصول التطبيق إلى المستودع
لا تصل الـwebhooks، فلا يُفجَّر أي بناء عند الدفع.

**الحل الدائم (يحتاج حساب GitHub الخاص بك):** ثبّت/فوّض
[تطبيق Railway على GitHub](https://github.com/apps/railway-app) على مستودع
`shary17454/my-codex`، ثم أعد ربط المصدر مرة واحدة.

**الحل المؤقت حتى ذلك** — أعد الربط بعد كل دفعة تمسّ الخادم:

```sh
cd ios/BatalAlDroob/ai-backend
railway service source disconnect --service batal-ai-backend
railway service source connect --repo shary17454/my-codex --branch main --service batal-ai-backend
```

**تنبيه:** `railway redeploy` يعيد نشر **نفس الصورة** ولا يبني من كوميت أحدث — تطابق
الـdigest هو ما يكشف ذلك.
